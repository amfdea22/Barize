# TC-001: Redesign da Tela de Login — NeonBar Pro

**Status**: active
**Criado em**: 2026-07-20
**Prioridade**: high

---

## 1. Objetivo

Redesign da tela de login do NeonBar para replicar fielmente o protótipo visual `login_neonbar_pro_pt`, substituindo o layout atual (card centralizado simples) pelo layout split com imagem de fundo, TopAppBar, tipografia neon e todos os elementos do protótipo.

## 2. Descrição

A tela de login atual (`Login.tsx`) é um layout centralizado vertical simples com logo Beer + "NeonBar", campos "Usuário" e "Senha", e botão "Entrar" sem glow. O protótipo (`code.html`) apresenta um design significativamente mais rico e premium com os seguintes elementos visuais a serem implementados:

| Elemento | Protótipo (code.html) | Atual (Login.tsx) |
|---|---|---|
| **Layout** | Split: left (imagem bg) + right (formulário) | Centralizado simples |
| **TopAppBar** | Fixa com "NeonBar Pro" + botão ajuda | Ausente |
| **Background left** | Imagem de bar premium com overlay gradiente | Ausente |
| **Left content** | Badge "Sistema Operacional", heading "Maximize seu fluxo.", descrição | Ausente |
| **Título do form** | "Bem-vindo, Capitão." | "NeonBar" + Beer icon |
| **Subtítulo** | "Acesso seguro ao terminal de operações." | "ERP para Gestão de Bares" |
| **Campo identidade** | "IDENTIDADE DO OPERADOR" com ícone person | "Usuário" com ícone User |
| **Campo senha** | "SENHA / PIN SEGURO" com ícone lock + "Esqueceu a senha?" | "Senha" com ícone Beer |
| **Lembrar de mim** | Checkbox estilizado | Ausente |
| **Botão Entrar** | Glow neon cyan (#00daf3) + ícone login | Sem glow, sem ícone |
| **Footer** | Links: Suporte, Segurança, Privacidade + copyright | Badge "v1.0.0 · Ambiente Seguro" |
| **Ícones** | Material Symbols | lucide-react |
| **Tipografia** | Inter (headings/body) + JetBrains Mono (labels) | System fonts / CSS variables |
| **Efeitos** | Backdrop blur, neon border, autofill styling, noise texture | Apenas background glow sutil |

## 3. Aceite Técnico

- [ ] Layout split responsivo: left hidden em mobile (< md), visible em desktop
- [ ] TopAppBar fixa com "NeonBar Pro" e botão de ajuda (ícone Material Symbols `help_outline`)
- [ ] Imagem de fundo no lado esquerdo com overlay gradiente (dark → transparent)
- [ ] Badge "Sistema Operacional" com ícone pulsante e backdrop blur
- [ ] Headings "Maximize seu fluxo." e descrição no lado esquerdo
- [ ] Título "Bem-vindo, Capitão." e subtítulo "Acesso seguro ao terminal de operações."
- [ ] Campo "IDENTIDADE DO OPERADOR" com ícone person e placeholder "E-mail ou nome de usuário"
- [ ] Campo "SENHA / PIN SEGURO" com ícone lock, placeholder "••••••••" e link "Esqueceu a senha?" (cor amber)
- [ ] Checkbox "Lembrar de mim" estilizado com ícone check
- [ ] Botão "Entrar" com glow neon cyan (#00daf3) e ícone login
- [ ] Footer com links Suporte, Segurança, Privacidade e copyright "© 2024 NeonBar Pro. Sistemas operacionais."
- [ ] Cores do tema escuro aplicadas (surface, primary-fixed-dim, secondary, etc.)
- [ ] Tipografia: Inter para headings/body, JetBrains Mono para labels
- [ ] Efeitos: neon glow no botão, neon border focus nos inputs, backdrop blur, autofill styling
- [ ] Funcionalidade de login existente preservada (hook useAuth, validação, loading state, error state)
- [ ] Loading state no botão com spinner + "Conectando..."
- [ ] Background glow radial no lado direito

## 4. Escopo

### Inclui
- `neonbar/frontend/src/pages/Login.tsx` — rewrite completo do JSX e estilos
- `neonbar/frontend/src/components/` — criação/aditamento de componentes se necessário (ex: checkbox customizado, ícones Material Symbols)
- Variáveis CSS / Tailwind config se precisar estender para suportar as cores e efeitos do protótipo

### Não inclui
- Lógica de autenticação (manter hook `useAuth` inalterado)
- Backend ou API
- Outras páginas além do login
- Tradução/i18n
- Testes automatizados (apenas verificação visual manual)

## 5. Guardrails

- Não quebrar funcionalidade de login existente (validação, loading state, error state, redirect)
- Preservar hook `useAuth` e seu uso (`login`, `isAuthenticated`)
- Preservar navegação pós-login (`useNavigate`, redirect to `/`)
- Manter acessibilidade: labels, focus states, roles
- Não modificar `opencode.json` ou config files do projeto
- Não instalar dependências sem aprovação
- Código deve passar lint e type checking do frontend (verificar config TS do projeto)

## 6. Restrições

- Manter React + TypeScript + Tailwind CSS (não migrar para CSS puro)
- Ícones: usar Material Symbols (via Google Fonts CDN ou npm package) ou manter lucide-react com substituição por equivalentes visuais
- A imagem de fundo deve usar a mesma URL do protótipo ou ser substituída por placeholder local
- O efeito neon glow deve usar `box-shadow` com `rgba(0, 218, 243, 0.2)` conforme protótipo
- Manter suporte a mobile (left side hidden em < md)
- Respeitar a paleta de cores definida no protótipo (surface, primary-fixed-dim, secondary, etc.)

## 7. Arquivos Envolvidos

- `neonbar/frontend/src/pages/Login.tsx` — arquivo principal a ser modificado (rewrite do JSX)
- `neonbar/frontend/src/components/` — possíveis novos componentes:
  - Checkbox estilizado (se não existir)
  - TopAppBar (se não existir componente genérico)
  - Wrapper para Material Symbols (se optar por componente próprio)
- `neonbar/frontend/src/index.css` ou `App.css` — possível extensão de variáveis CSS / estilos globais para autofill, neon effects

## 8. Dependências

Nenhuma. Card independente.

## 9. Testes

- Verificação visual: comparar com protótipo `code.html` em desktop e mobile
- Responsividade: testar em viewport < 768px (mobile) e > 768px (desktop)
- Funcional: login deve continuar funcionando (validação, loading, erro, redirect)
- Acessibilidade: tab order, labels, focus states
