# TC-002: Corrigir erro de schema no banco de testes — coluna `controlado` ausente

**Status**: completed
**Criado em**: 2026-07-20
**Prioridade**: high

---

## 1. Objetivo

Corrigir o erro `sqlite3.OperationalError: table insumos has no column named controlado` que ocorre ao executar os testes com `pytest`.

## 2. Descrição

O modelo `Insumo` em `backend/app/models/insumo.py` possui o campo `controlado` (adicionado na migration 0011). Porém, ao executar os testes, o SQLite levanta `OperationalError: table insumos has no column named controlado` porque o arquivo `test_neonbar.db` já existe de uma execução anterior com schema desatualizado.

`Base.metadata.create_all()` não altera tabelas existentes — apenas cria as que não existem. Como o arquivo persistiu entre execuções, a coluna `controlado` nunca foi adicionada.

## 3. Aceite Técnico

- [ ] `pytest -x --tb=short` executa sem erro de schema
- [ ] Testes existentes continuam passando (mínimo 6 testes)
- [ ] Banco de testes é recriado do zero a cada execução ou o schema é sempre atualizado
- [ ] Nenhum dado de produção é afetado (apenas ambiente de teste)

## 4. Escopo

### Não inclui

## 6. Restrições

- Não adicionar dependências externas
- Solução deve funcionar em Windows e Linux
