# TC-003: Padronização e Organização de Componentes e Páginas Frontend

**Status**: completed
**Criado em**: 2026-07-20
**Prioridade**: high

---

## 1. Objetivo

Padronizar todas as 8 páginas e 8 componentes do frontend para usar tokens de design consistentes, eliminar cores hardcoded, remover duplicação de estilo inline, extrair componentes reutilizáveis, e garantir conformidade com o DESIGN.md e o protótipo `login_neonbar_pro_pt/code.html`.

## 2. Descrição

Após análise completa do codebase, os seguintes problemas foram identificados:

### 2.1 Componentes (8 arquivos)

| Componente | Arquivo | Problemas |
|---|---|---|
| Badge | components/Badge.tsx | Variante success usa bg-emerald-500/15 text-emerald-400 (hardcoded). Variante warning usa bg-amber-500/15 text-amber-400 (hardcoded). Variante info usa bg-sky-500/15 text-sky-400 (hardcoded). Nenhuma dessas cores existe como token de design. |
| Button | components/Button.tsx | Variante ghost-white usa border-[rgba(255,255,255,0.15)]. Tamanho sm tem min-h-[32px] viola touch-target de 48px do DESIGN.md. |
| Card | components/Card.tsx | Hover usa bg-[var(--color-surface-high)] token surface-high nao existe em index.css (deveria ser surface-container-high). |
| Chip | components/Chip.tsx | Inactive usa bg-[var(--color-surface-low)] token surface-low nao existe (deveria ser surface-container-low). |
| DataTable | components/DataTable.tsx | Usa zebra-striping (idx mod 2 === 0) DESIGN.md explicitamente desencoraja. Alternativa: usar separadores finos via border-b. |
| Input | components/Input.tsx | Usa bg-[var(--color-surface-low)] token nao existe. Sempre aplica pl-[44px] mesmo sem icone, criando padding desnecessario. |
| Modal | components/Modal.tsx | Backdrop usa bg-black/60 nao usa tokens de design. Tamanho xl definido mas nao usado em nenhuma pagina. |
| StatsCard | components/StatsCard.tsx | Nao tem variante error em variantStyles, mas CMV.tsx passa error como variant. Icone usa bg-[var(--color-primary)]/10 primary nao e cor de background. Deveria usar primary-container. |

### 2.3 Problemas Transversais

1. Token surface-low nao existe: Referenciado em Input.tsx, Chip.tsx --color-surface-low nao esta em index.css. O token correto e --color-surface-container-low.
2. Token surface-high nao existe: Referenciado em Card.tsx --color-surface-high nao existe.
3. Mistura de convencoes de estilo: Login.tsx usa string inline inputBase, outras paginas usam Input. Alguns lugares usam Tailwind v4 bg-surface-container-low, outros usam bg-[var(--color-surface-container-low)].
4. Cores hardcoded espalhadas: Verde (rgb(0,200,83)), Amber (amber-*), Esmeralda (emerald-*), Sky (sky-*) nenhuma delas existe como token de design.
5. Componentes duplicados: OrderCard (Dashboard.tsx), ReceitaEditorContent (PDV.tsx) deveriam ser extraidos para components/.
6. Sem sistema de notificacao: Cada pagina implementa feedback de erro/sucesso de forma diferente.
7. Sem loading skeletons: Todas as paginas usam texto Carregando... em vez de componentes de skeleton.
8. Zebra-striping no DataTable: DESIGN.md proibe explicitamente.
9. Missing error variant: StatsCard nao suporta variant error, mas CMV.tsx usa.

## 5. Guardrails

1. Nao quebrar funcionalidade existente cada pagina deve funcionar exatamente como antes apos refatoracao
2. Usar tokens existentes se o token existe em index.css, usa-lo. Nao criar novos tokens sem necessidade
3. Tailwind v4 com theme preferir sintaxe bg-surface-container-low sobre bg-[var(--color-*)]
4. Touch targets minimos de 48px DESIGN.md secao Layout and Spacing
5. Extracao de componentes so extrair se usado em mais de um lugar ou se o arquivo da pagina ficar maior que 400 linhas
6. Commits parciais fazer commits por pagina/grupo logico, nao um commit gigante

## 6. Restricoes

1. Login.tsx deve corresponder ao prototipo code.html mesmas classes, mesma estrutura, mesmos tokens
2. Nao adicionar novas dependencias usar apenas React, Tailwind v4, lucide-react ja existentes
3. Nao modificar index.css a menos que seja para adicionar tokens que existem no DESIGN.md mas nao estao mapeados
4. Manter dark mode todas as paginas ja estao em dark mode, nao mudar
5. Preservar animacoes existentes animate-fade-in, animate-slide-in, animate-pulse-glow devem continuar funcionando
