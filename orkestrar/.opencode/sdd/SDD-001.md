# SDD-001: Recuperar Imagens e Funcionalidades do Menu Comandas

**Status**: `draft`
**Autor**: build
**Criado em**: 2026-07-30

---

## 1. Contexto

O menu Comandas (KDS — Kitchen Display System) exibe pedidos da cozinha/bar mas não possui:

- Imagens dos produtos nos itens do pedido
- Botões para avançar o status (Novo → Preparando → Pronto → Entregue)
- Ordenação inteligente por urgência
- Auto-refresh dos dados

O backend já possui o endpoint `PATCH /pedidos/{id}/status` e os produtos já possuem `foto_url`/`imagem` no banco. O PDV já estabeleceu o padrão de fallback visual (`foto_url → imagem → fallback`).

## 2. Objetivos e Não-Objetivos

- **Goals**:
  - Exibir thumbnail dos produtos nos itens expandidos de cada comanda
  - Adicionar botões de ação para avançar status diretamente no card
  - Ordenar pedidos: Pronto → Preparando → Novo
  - Auto-refresh da lista a cada 15s
  - Substituir ícone genérico do card pela thumbnail do primeiro item

- **Non-goals**:
  - Não alterar o modal de impressão
  - Não alterar o modal de edição
  - Não criar novos endpoints — apenas consumir os existentes

## 3. Arquitetura Proposta

### 3.1 Visão Geral

Todas as mudanças são **front-end apenas** (`Comandas.tsx`). Nenhuma alteração no backend.

O fluxo de dados:

```
[GET /produtos/] → lookup table (nome → foto_url/imagem)
[GET /pedidos/]  → lista de pedidos
                     ↓
               Comandas.tsx
                 ├── merge produtos lookup nos itens
                 ├── render thumbnail + fallback
                 ├── botões de status contextuais
                 └── sorted + auto-refresh
```

### 3.3 Data Model

Nenhum modelo novo. O lookup é feito em memória:

```typescript
// Comandas.tsx — estado adicional
const [produtosLookup, setProdutosLookup] = useState<Record<string, { foto_url?: string; imagem?: string }>>({});

// useEffect — carregar lookup table
useEffect(() => {
  pdvService.listarProdutos().then(res => {
    const map: Record<string, any> = {};
    res.data.forEach((p: Produto) => { map[p.nome.toLowerCase()] = p; });
    setProdutosLookup(map);
  });
}, []);
```

### 3.4 Fluxo de Dados

1. **Mount**: `GET /produtos/` → constrói lookup table (nome → `foto_url`/`imagem`)
2. **Mount + 15s interval**: `GET /pedidos/` → lista de pedidos
3. **Render**: cada item do pedido faz lookup no map → exibe thumbnail com fallback de 3 níveis
4. **Ação**: clique em botão de status → `PATCH /pedidos/{id}/status` → refresh da lista

## 4. Alternativas Consideradas

| Alternativa | Prós | Contras | Decisão |
|------------|------|---------|---------|
| Incluir `foto_url` no JSON do PedidoItem no backend | Dados já vêm prontos | Migração de dados, mudança no schema, acoplamento | ❌ |
| Lookup em memória no front | Sem mudanças no backend, rápido | Requer carregar produtos uma vez | ✅ |
| Auto-refresh via WebSocket | Tempo real, sem polling | Complexidade adicional, infra | ❌ |

## 5. Segurança

- Nenhum dado sensível é transmitido
- Endpoints já protegidos por `get_current_user` (JWT)
- Imagens servidas via `/uploads/` (já protegido pelo middleware de autenticação)

## 6. Plano de Implementação

### Fase 1 — Lookup de imagens e thumbnails nos itens

Arquivo: `frontend/src/pages/Comandas.tsx`

1. Adicionar estado `produtosLookup: Record<string, { foto_url?: string; imagem?: string }>`
2. No mount, carregar `pdvService.listarProdutos()` e construir o map
3. No render dos itens expandidos (linha 261-275), exibir thumbnail 32x32 com fallback:
   ```
   produtosLookup[item.nome.toLowerCase()]?.foto_url
     → <img src={...} />
     → produtosLookup[item.nome.toLowerCase()]?.imagem
       → <span>{imagem}</span>
       → <ShoppingCart size={16} />
   ```
4. No cabeçalho do card (linha 194), substituir `ShoppingCart` pela thumbnail do primeiro item

### Fase 2 — Botões de ação de status

1. Adicionar botões contextuais no card summary (após o botão de editar):

| Status | Botão | Destino |
|--------|-------|---------|
| Novo | "Iniciar" (amarelo) | Preparando |
| Preparando | "Pronto" (verde) | Pronto |
| Pronto | "Entregar" (cinza) | Entregue |

2. Chamar `pedidosService.atualizarStatus(id, novoStatus)` no clique
3. Em caso de sucesso, refresh automático da lista
4. Desabilitar botão durante a requisição (loading state)

### Fase 3 — Ordenação e auto-refresh

1. Antes de filtrar, ordenar: `Pronto` primeiro, depois `Preparando`, depois `Novo`, depois `Entregue`
2. Dentro do mesmo status, manter ordenação por `created_at` decrescente
3. Adicionar `setInterval` de 15s para recarregar `GET /pedidos/`
4. Limpar intervalo no cleanup do `useEffect`
